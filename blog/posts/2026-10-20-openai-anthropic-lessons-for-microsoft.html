What Microsoft Should Actually Steal from the Latest AI Labs

AR Akhil Reddy Danda · 20th October, 2026 · 2 min read

Watching the latest OpenAI and Anthropic launches, the lesson isn’t "ship bigger models." It’s about tooling and agentic process. Anthropic’s Code interpreter and OpenAI’s new eval-first APIs create end-to-end workflows—plan, code, test, refactor—inside the IDE and CI/CD. Microsoft still doesn’t have this, even with Copilot and Azure AI Studio.

What’s missing? Eval-driven development as a first-class primitive. Azure and GitHub build tools should treat evaluation scripts, correctness loops, and agent orchestration as native citizens. When I wire up a Copilot workspace, I want to specify evals and let agents loop until they pass—like Anthropic’s Claude Code does out of the box. Right now, developers are forced to hack together test runners and hope Copilot pays attention. That’s friction engineers notice.

Another lesson: Open, composable tool APIs. Anthropic’s MCP servers let developers wire up their own analyzers, linters, or security scanners—agents call them and adapt in realtime. Microsoft’s toolchains are still too closed: you get what the product team ships. If Azure and GitHub want to win, they need to unlock this agentic flexibility—let devs register tools, define loops, and build custom agent chains inside the Microsoft ecosystem.

It comes down to this: If Microsoft doesn’t make agentic, eval-driven workflows the default, next-gen developer velocity will happen elsewhere. Stop focusing just on model parameters. Focus on making agents and loops as programmable, composable, and testable as the code itself. That’s what’s making the frontier labs move faster.
