What Microsoft Should Actually Steal Next: Lessons From OpenAI and Anthropic on Agentic APIs and Eval-First Dev

AR Akhil Reddy Danda · 27th October, 2026 · 2 min read

I use Microsoft’s Copilot and Azure daily, but let’s be honest: they’re lagging behind OpenAI and Anthropic when it comes to programmatic, agentic APIs. Developers want to orchestrate AI agents with plan-act-verify loops, build with spec-driven prompts, and ship with eval-based assurance. Microsoft needs to stop chasing flashy UI and start building open agentic primitives.

Agentic APIs: Make Them Open and Auditable

OpenAI’s functions and Anthropic’s Claude Code expose low-level agentic flows and let devs plug in their tools. Microsoft’s Copilot APIs are too closed, too high-level. If Copilot wants to be more than fancy autocomplete, it needs granular control: routing, tool orchestration, and eval hooks. Why? Because serious engineers want to control and audit the loop, not just “suggest” code.

Eval-First Workflows: Build for Testability

GitHub and Azure should offer prompt test suites, eval runners, and MCP (multi-tool server) integrations out of the box. Anthropic and OpenAI are moving fast here—making it easy for devs to author evals, run them in CI, and plug in custom tools. If Microsoft doesn’t, engineers will keep bolting on third-party solutions, and Copilot will lose ground.

Spec-Driven Prompting: Ship With Confidence

Azure’s AI workflows should start with structured specs—not just conversational prompts. If you want reliability, you need deterministic flows: spec in, agent acts, evals verify. Open the API, let devs run their own loops, and build for auditability.

Bottom line: Microsoft needs to ship open agentic APIs, eval-first dev tools, and structured prompting. Otherwise, engineers will keep jumping ship to OpenAI, Anthropic, and Google. Steal the right primitives, and Copilot becomes a serious platform—not just a UI feature.
