Microsoft Needs Eval-First, Spec-Driven Agentic Workflows: What Copilot Should Learn from Claude and Gemini

AR Akhil Reddy Danda · 4th November, 2026 · 2 min read

Copilot and Azure AI are great at autocomplete and Q&A, but they’re falling behind on agentic workflows. The real shift is happening with Claude Code (Anthropic) and Gemini Code (Google): open agent APIs, spec-driven prompting, and eval-first loops. Microsoft’s developer ecosystem (Azure, GitHub, Foundry, Windows) needs to adopt these patterns, not just add more chat UIs.

Why This Matters

Engineers want tools that reason about specs, not just code fragments. Spec-driven prompting clarifies intent, so agents can plan, act, verify, and fix—autonomously. Eval-first loops (where tests and eval criteria drive agent correction) deliver higher quality code and fewer regressions. Open APIs mean you can orchestrate multiple agents, tools, and test infra, customizing for your workflow. Microsoft’s closed Copilot APIs limit this flexibility, forcing engineers into narrow use-cases.

Concrete Steps Microsoft Should Take

Open agent APIs—let engineers run persistent, multi-step agents on GitHub/Foundry, not just chat bots. Make spec-driven prompting a first-class feature (integrate with PR templates, Azure DevOps specs). Build eval-first loops into Copilot: let agents run and verify code against custom eval scripts, not just static linters. And finally, support tool server orchestration: allow agents to invoke CLI tools, CI systems, and third-party APIs directly.

If Microsoft doesn’t move, engineers will bolt on Claude/Gemini agents anyway. The new workflow is open, eval-driven, and spec-first. That’s where real productivity gains are.
