What Microsoft Must Copy Next: Open Memory APIs, Agent Protocols, and Eval-Driven Dev

AR Akhil Reddy Danda · 13th November, 2026 · 2 min read

Let’s be blunt: Microsoft’s Copilot and Azure AI suite are solid, but if you’re shipping AI-powered products as an engineer, you crave the new hotness—stuff we’re seeing hinted at by OpenAI and Anthropic. What’s missing? Three things: open memory APIs, agentic protocol standards, and eval-first workflows baked into the platform.

Memory APIs: State Beyond the Session

Right now, Copilot and Azure OpenAI mostly treat sessions as stateless. But look at OpenAI’s direction: real developer-level memory APIs for persistent, user-scoped, and tool-addressable state. This is how you make genuinely helpful agents that can learn, personalize, and act contextually, not just autocomplete the next line. Microsoft needs to standardize and ship memory primitives—think memory slots, scratchpads, and shareable state objects—for devs to build true multi-turn, context-aware AI.

Agent Protocols: Don’t Reinvent, Interoperate

Anthropic and OpenAI are both pushing toward open agent protocols—modular interfaces for tools, environments, and multi-agent orchestration. Microsoft should embrace these, not wall off with proprietary extensions. Imagine if Copilot or Azure AI agents could plug-and-play with OSS tools, third-party APIs, or even cross-cloud agents. That’s what engineers want: composability, not lock-in.

Eval-Driven Development: From Theory to Default

Every serious AI dev now builds with eval loops—continuous, automated harnesses that test, score, and let agents self-improve. Microsoft’s eval features are buried, inconsistent, and not a first-class part of the Copilot or Azure dev story. That’s a huge miss. Engineers need battle-tested eval flows, not "trust us" black boxes.

Why it matters: If Microsoft really wants to win developer mindshare, not just enterprises, it needs to build for agentic, memory-aware, eval-native workflows. Don’t wait for OpenAI and Anthropic to define the future. Steal their best ideas, open it up, and let engineers run wild.
