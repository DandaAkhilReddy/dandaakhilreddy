What Microsoft Should Learn Next: Tool Trust, Eval APIs, and Open NFN Patterns

AR Akhil Reddy Danda · 21st October, 2026 · 2 min read

Microsoft has shipped a ton of AI—Copilot, Azure AI Studio, Foundry, GitHub’s new agentic features. But as OpenAI, Anthropic, and Google deploy truly open evaluation APIs and sandboxed tool trust patterns, it’s time for Microsoft to play catch-up in a few specific areas.

What Needs to Change?

First, Eval-first APIs: OpenAI’s model eval endpoints and Anthropic’s agent test harnesses let devs plug in custom evals, directly in the agentic loop. Microsoft’s eval flows are still too closed, buried in internal telemetry. Engineers want to wire up their own tests, run local evals, and get granular scores—just like they would with CI/CD. Without this, Copilot workflows struggle at scale.

Second, Tool Trust Infrastructure: Google’s Vertex NFN (Named Function Network) gives devs fine-grained controls for what AI agents can call, and a transparent log of every action. The current Azure and Copilot agent toolchains aren’t robust enough here—too many opaque permissions, not enough developer-facing guarantees or auditability. If an agent is going to call a billing API, I need to know, log, and limit that, period.

Engineers inside Microsoft: push for these changes. Open eval APIs and transparent tool trust will make Copilot and Azure agents not just powerful, but safe and verifiable.
