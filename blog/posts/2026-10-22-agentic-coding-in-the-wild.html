Agentic Coding in the Wild: How Modern Devs Actually Use AI (and What Still Sucks)

AR Akhil Reddy Danda · 22nd October, 2026 · 2 min read

Let’s ignore the hype and look at how developers are actually using AI this month. The big story? Agentic coding is now standard—not science fiction. Teams are running Claude or Claude Code (Anthropic’s new agentic workspace) as a background process, no longer just “prompting” a chatbot. You write a spec, the agent plans a change, executes an action (code, test, refactor), verifies with CI or custom evals, and loops again. This plan→act→verify→fix loop matters because it matches how we really work: code rarely ships in one shot, and AI finally gets that.

Loop Engineering: The Real Workflow

Building robust evals (see eval-driven dev) is now part of our job. You ship an eval, wire it to your agent, and let the loop run until it passes or hits a real blocker. MCP tool servers are also picking up steam—think: your own local tool API that the agent can call (codegen, SQL, curl) without leaking secrets or hitting latency walls. It’s like giving your AI pair-programmer a proper dev environment.

Spec-Driven Prompts: No More Vague Intents

Prompting has matured, too. Instead of “Build me a login page,” you treat the prompt like a contract: inputs, outputs, edge cases, sometimes even test coverage. The AI respects those specs, and you avoid the endless “try again” cycles.

What Still Sucks

Debugging agentic loops is still rough. When you’re three tools deep and the agent’s logic diverges, you need better observability (logs, traces, replay). We’re starting to steal ideas from distributed tracing to debug these workflows.

Why it matters: The gap between "AI as assistant" and "AI as co-dev" is closing. But only if we give it the scaffolding: evals, tool servers, spec-first prompts, and real feedback loops. The future isn’t prompt engineering—it’s loop engineering.
